# Physical Risk: 자산 좌표 기반 전환 업데이트

**브랜치**: `feature/asset-level-physical-risk`
**작성일**: 2026-06-04

---

## 1. 브랜치 목적

기존 물리적 리스크 모델은 한국을 6개 권역으로 나눠 권역 평균값을 모든 자산에 일괄 적용했다.
이로 인해 서로 다른 위치의 자산이 동일한 위험값을 가지는 문제가 있었다.

이 브랜치는 홍수·폭염·가뭄 3개 hazard를 **자산의 실제 좌표 기반 ERA5 기후 데이터**로 전환하고,
전환 과정에서 필요한 안전장치(데이터 소스 추적, API 실패 경고, 캐시)를 함께 구현한다.

---

## 2. 변경 전/후 요약

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 홍수 Gumbel 파라미터 | 6개 권역 테이블 (config.py 하드코딩) | 자산 좌표 → ERA5 30년 강수 데이터 직접 피팅 |
| 폭염일수 기준값 | 6개 권역 테이블 | 자산 좌표 → ERA5 일최고기온 33°C 초과일 직접 계산 |
| 가뭄일수 기준값 | 6개 권역 테이블 | 자산 좌표 → ERA5 연속 무강수일 직접 계산 |
| 태풍 빈도 | 6개 권역 테이블 | 변경 없음 (정적 권역 기반 유지) |
| 해수면 상승 | 해안/내륙 이진 분류 | 변경 없음 |
| 데이터 소스 추적 | 없음 | hazard별 `data_source` 필드 추가 |
| API 실패 알림 | 조용히 fallback | `api_warnings` 필드 + WARNING 로그 |
| 캐시 키 | 좌표만 | 좌표 + 기간 + 변수명 |
| Streamlit 표시 | data_source 없음 | 테이블에 데이터 소스 컬럼, 경고 배너 표시 |

---

## 3. ERA5 좌표 기반으로 변경된 hazard

**홍수 / 폭염 / 가뭄** — `use_api_data=True` (현재 기본값)

- 데이터 소스: Open-Meteo Archive API → ECMWF ERA5 (1994-2023, 30년)
- 자산 좌표를 직접 요청하므로 권역 분류 오류 없음
- 결과에 `"data_source": "open_meteo_era5"` 표시

---

## 4. 정적 권역 기반으로 유지되는 hazard

**태풍 / 해수면 상승** — 항상 `"data_source": "static_config"`

- 태풍: Open-Meteo에 경로 데이터 없음. IBTrACS 연동 필요 (후속 과제)
- 해수면 상승: IPCC AR6 공식 기반 계산. 해안 여부는 경도 임계값으로 이진 판단
- 두 hazard는 `api_warnings`에 자동 기록되어 사용자에게 표시됨

---

## 5. Static 대비 API 결과 차이

동일 자산, 동일 시나리오(current_policies, 2030) 기준:

| Hazard | 서울 | 부산 | 제주 | 방향 |
|--------|------|------|------|------|
| 홍수 손실 | -41.7% | -51.8% | -44.5% | API가 낮음 |
| 폭염 손실 | -77.3% | -75.0% | -86.8% | API가 훨씬 낮음 |
| 가뭄 손실 | +12.1% | +35.7% | +20.2% | API가 약간 높음 |

**해석**: 기존 config.py의 하드코딩 값(특히 폭염일수)이 ERA5 실측 대비 크게 과대추정되어 있었음.
홍수 Gumbel 파라미터도 권역 평균이 실제 좌표값보다 높게 설정되어 있었음.

## 6. 캐시 적용 — 재실행 속도 개선

| 실행 | 시간 | HTTP 호출 |
|------|------|----------|
| 첫 실행 (cold cache) | ~15초 | 자산당 1회 |
| 재실행 (warm cache, 1시간 TTL) | 0.001초 | 0회 |

캐시 키: `{lat},{lon}|{start_date}|{end_date}|{variables}`
→ 날짜·변수가 바뀌면 자동 무효화.
`get_cache_stats()` 함수로 hit/miss 통계 확인 가능.

## 7. 남은 한계와 후속 과제

| 한계 | 후속 과제 |
|------|----------|
| 태풍 빈도가 6개 권역 평균에 의존 | IBTrACS (NOAA) 경로 데이터 연동 → 좌표 기반 태풍 빈도 계산 |
| 해수면 상승이 해안/내륙 이진 판단 | NASA SRTM 고도 + 해안선 거리 기반 침수 확률 계산 |
| API rate limit (429) 발생 시 전체 fallback | 지수 백오프 재시도 또는 사전 캐시 워밍 구현 |
| 캐시가 프로세스 내 메모리 (재시작 시 초기화) | 디스크 캐시 또는 Redis 연동 검토 |
| 홍수 모델이 강수량만 사용 (지형·배수 미반영) | SCS Curve Number 또는 수리·수문 모델 연동 |
| config.py의 6개 권역 파라미터가 여전히 존재 | API 실패 fallback 용도로 유지하되 출처 주석 보강 필요 |
